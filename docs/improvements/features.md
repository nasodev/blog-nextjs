## 확인된 문제와 구현

| 우선순위 | 근거 | 문제/필요 | 구현 |
|---|---|---|---|
| 높음 | `components/Contact/ContactForm.tsx` | 문의 제출이 console.log뿐이며 운영 빌드에서는 이것도 제거됨 | 이름·이메일·문의 필수 입력과 길이 제한을 갖춘 폼. encodeURIComponent로 안전하게 인코딩한 이메일 초안을 기본 이메일 앱에 전달 |
| 중간 | 글 상세 | 방문자가 글 주소를 쉽게 공유할 경로가 없음 | 한국어/영어 링크 복사 버튼. 성공 안내와 클립보드 거부 시 직접 선택 가능한 주소 제공 |
| 중간 | `components/Footer/index.tsx` | RSS 엔드포인트가 있으나 구독 링크를 찾기 어려움 | 한국어/영어 RSS를 푸터에 노출. 연도도 현재 연도로 표시 |

문의 버튼은 **이메일 앱에서 작성**이며, 사이트가 이메일을 발송했다고 표시하지 않는다. 방문자가 이메일 앱에서 직접 전송한다. 앱이 없는 경우에도 연락 주소를 항상 볼 수 있다. 서버로 문의 내용을 전송하거나 저장하지 않는다.

## 검증

- lint·route typegen·TypeScript 검사 통과.
- `tests/features.spec.ts`와 기존 i18n 검사: 2건 통과. 한글·줄바꿈·특수문자가 수신자나 별도 메일 헤더를 바꾸지 않는지 확인.
- `tests/features.browser.spec.ts`: 복사 성공/권한 거부, 필수 입력, 연락 주소, 두 RSS 링크 확인. 통합 실행 결과는 최종 보고서 참조.

## 추후 추가할 기능과 조건

- 서버에서 문의를 접수해야 한다면 기존 backend에 발송 API·입력 검증·스팸 제한·개인정보 보관 정책을 함께 추가한다.
- 글이 늘고 재방문 수요가 확인되면 북마크/읽은 글 표시를 검토한다. 계정·DB를 새로 만들지 않았다.
- 시리즈 연재가 실제로 생기면 시리즈별 순서/목록을 도입한다. 현재는 기존 태그·관련 글·이전/다음 글이 탐색을 담당한다.
